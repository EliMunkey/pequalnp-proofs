# Independent exhaustive replay

Run `python3 independent.py --all` from this directory, or give Python the absolute path to `independent.py` from another directory. Python 3.10+ and a C++17 compiler named `c++` are required. No network access or external datasets are used. Binaries are created in a temporary directory and removed on completion. The optional Lean accounting lemmas use the standard library of Lean 4.36.0. They can each be checked with `lean` and their filename. `python3 independent.py` validates the input tables and automorphism orbits on their own.

The script checks the given truth tables from the 15 explicit Petersen edges. Each restricted function is a disjunction of independent singleton variables and an edge function for a smaller graph. Appending an independent singleton to a nonconstant function adds exactly one binary gate, since pinning it to zero removes a reader and a final OR achieves that cost. Isolated vertices are eliminated, and the graph component is classified up to vertex permutation. The script verifies the costs of all 16 component masks of size at most seven by rerunning both sides of each minimum. It then verifies the two eight-input classes, the nine-input lower bound, and the ten-input bound at size 17 over arbitrary signed binary AND gates with free complements (U2). The twelve-gate positive eight-input control and the minimum-size component controls establish that the U2 search can both accept and reject.

`replay.cpp` evaluates U2 gates by their truth tables. A minimum DAG can be scheduled so that each signal retires on its last use. Each step selects two live signals, any of four signed-AND patterns, and one of four operand retention choices. The representative of each truth function has value zero on the all-zero input, using free signs on its readers. Constant, repeated, and complementary duplicate functions can be bypassed. The live frontier must separate all pairs of opposite target rows. A gate changes only the two coordinates it reads, so single-coordinate and double-coordinate conflicts suffice to test any resulting loss of distinguishability. When `L` wires remain live, at least `L−1` future binary instructions must combine them into the final sink. For equal live functions the same suffix is feasible. Memoization stores the largest exhausted suffix budget and resolves hash collisions by checking the complete key.

For every restriction, count eliminated gates plus live wires known constant. The count starts at the number of pinned inputs. A gate with a known operand is replaceable by a literal or a constant. The count increases once for each retained constant operand, and once more when exactly one operand is constant and alone forces the gate output. At the end, the sole live signal is the nonconstant target, so this accumulated count equals the number of eliminated gates. If a cofactor costs `b` and the current count plus `b` exceeds the original size budget, a computing circuit cannot complete this prefix. The C++ implementations use direct per-restriction arithmetic. The ARM64 physical implementation updates sixteen signed bytes in parallel using the same arithmetic. The portable scalar fallback is included. `PinPotential.lean` proves abstraction soundness, gives and checks the zero-gate replacements, verifies the accounting identity for every signed binary gate, and telescopes valid traces.

`physical.cpp` covers AND/OR circuits with both signs of the marked physical input and positive rails for every other input. Every wire and the desired output are monotone on each fixed slice of the marked input. The minimal positive and maximal negative rows on each slice determine the entire target. All are retained, giving 38 rows in the ten-input problem. `PetersenBoundary.lean` checks the original 15-edge target, all 1,024 input rows, the labels of the listed 38 boundary rows, and proves that a monotone-on-slices candidate agreeing there agrees with the target everywhere. A required pair consisting of a positive and a negative row needs at least one live rail that equals one on the former and zero on the latter. If just one rail supplies the pair, its retirement obliges the new gate to supply both required values. If two rails supply it, the obligation arises only when both retire. The checker aggregates these obligations as positive and negative bit masks. A free marked input supplies either orientation and its two rails retire together.

At this physical stage, equal boundary functions can be substituted without changing the final answer, because every modified circuit still computes a monotone function on each slice. Stronger dominance substitutions apply as well. Write `w` better than `h` if every correctly classified boundary row for `h` is correctly classified for `w`. For positive rows this means `w≥h`. For negative rows it means `w≤h`. An AND/OR suffix preserves these comparisons on each row, as shown by `BoundaryDominance.lean`. A new gate dominated by an already available wire or constant can therefore be bypassed in a minimum circuit. Among minimum circuits, select one lexicographically maximizing first the sum of correct boundary bits across all gate outputs, then that sum across all operand reads. A strictly better one-gate expression of primary rails can replace the generating gate at the same cost, strictly improving the first score. If a retained ordinary wire is strictly dominated by the just-produced output, redirect one future read of the retained wire to the new output. Outputs can only improve, and if every output stays the same the changed operand strictly improves the secondary score. Thus those retained-wire configurations are impossible for the maximizing witness. The marked two-rail wire is exempt from forced retirement. The dominance filters use only the currently live wires and the original primary rails. Retired primary rails are still available in the underlying unrestricted DAG when proving such a replacement.

After the first gate, the checker chooses available gates in order of their maximum predecessor number, then their minimum predecessor number. A newly enabled gate refers to the newly assigned register, which puts it after previously available choices. The first gate is exempt, allowing an independent choice of a representative for its graph symmetry orbit. Memo keys in the physical checker include the source-register numbers and the previous ordering threshold. This makes their future eligibility identical. For a handful of the tightest restrictions the physical checker additionally computes the union of the surviving gate ancestry of the live signals after constant propagation. Its population count bounds the cost of reconstructing the live frontier. Each known-constant live wire also consumes a future gate elimination before a nonconstant sink is reached, by the same telescoping potential. This gives an upper bound for the completed restricted computation and can contradict the cofactor lower bound.

The two nine-vertex marked-input classes represent the marked vertex being adjacent or nonadjacent to the deleted vertex. Exactly 120 independently constructed Kneser relabelings cover all 90 ordered choices and all 45 unordered Petersen input pairs. The two physical size-15 negative controls thus establish a size-16 cofactor lower bound upon setting any single primary to zero in the final physical search. If the marked input itself is set to zero, the resulting monotone circuit is included in either nine-input test. The five- and six-input positive controls and a 12-gate eight-input positive control using 472 active restriction budgets are independently replayed on every original Boolean input, including the rows compressed away by the boundary representation.

The executable evidence is a finite computation. The Lean files prove the stated local lemmas and the 38-row reduction. The 17- and 18-gate search results are established by the executable replay.
